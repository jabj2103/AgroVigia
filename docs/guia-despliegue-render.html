Despliegue de AgroVigía en Render

Cómo publicar la web, n8n y la simulación para que funcionen juntos con Supabase y Gemini, usando solo el plan gratuito. Escrita para la rama camilo/integracion-ia-zonas.

Estado de esta guía. Los archivos de despliegue existen y se probaron en este equipo: la imagen de n8n construye y arranca con la simulación dentro, y las pruebas automáticas pasan. Lo que todavía no se ha hecho es desplegar en Render ni correr el recorrido contra tu proyecto real de Supabase. Donde un paso no se ha comprobado en la nube, lo digo.

1. Qué se despliega y cómo se conecta

Render solo expone HTTP y HTTPS al público. No puede publicar el puerto de MQTT, así que en la nube los datos viajan por HTTPS con el mismo contenido que hoy viaja por MQTT. El mensaje ya era JSON: MQTT era solo el transporte.

PiezaDónde correQué hace
WebRender, sitio estático agrovigia-webLa aplicación. Habla solo con Supabase, con la sesión del usuario.
n8nRender, servicio web agrovigia-n8nRecibe lotes por HTTP, los valida, los guarda en Supabase, abre y cierra alertas y pide sugerencias a Gemini.
SimulaciónDentro del mismo contenedor de n8nLee de Supabase el clima y el ajuste manual que eliges en la web y envía los lotes de los nodos simulados al webhook local de n8n.
SupabaseTu proyecto actualUsuarios, base de datos, permisos por cuenta y tiempo real.
GeminiServicio de GoogleRedacta las sugerencias. Lo llama n8n, nunca la web.

Recorrido de un cambio hecho en la web:

  1. En el Escenario activas un clima o mueves una regla. La web llama a establecer_clima o ajustar_simulacion en Supabase. Queda guardado con su hora de inicio.
  2. La simulación consulta estado_simulacion cada pocos segundos, calcula los valores de cada nodo y los envía a /webhook/agrovigia/telemetria.
  3. El flujo 03g de n8n valida el lote y lo registra con las mismas funciones que usa la ingesta por MQTT. Después evalúa las reglas y abre o cierra alertas.
  4. La web ve los valores nuevos en Inicio, Escenario, Historial y Alertas.
  5. Si pulsas "Analizar ahora", la web registra una solicitud. El flujo 03h la toma en menos de un minuto, llama a Gemini con el clima y el ajuste activos y guarda la sugerencia.
Por qué la simulación va dentro del contenedor de n8n. El plan gratuito da 750 horas de servicio web al mes para toda la cuenta. Un servicio encendido todo el mes usa unas 730. Dos servicios separados se quedarían sin horas a mitad de mes.

3. Preparar Supabase

La base ya tiene las migraciones 0001 a 0008. Faltan cuatro: 0009 (cultivos, clima y dispositivos), 0010 (IA y estado en vivo), 0011 (ajuste manual, sugerencias a petición, nodos simulados, mover y eliminar) y 0012 (medidas del terreno, sectores libres y nodos físicos con clave propia).

  1. En tu equipo, abre .local/secretos.env y completa SUPABASE_DB_URL y SUPABASE_SECRET_KEY. Ese archivo no entra a Git.
  2. Aplica las migraciones y los datos de ejemplo: 
    cd ~/Escritorio/AgroVIgia/AgroVigia-integracion
local/agrovigia.sh migrar
    El guion aplica solo lo que falte, crea los tres hexágonos de ejemplo y termina mostrando una fila de comprobaciones. Todas deben decir true.
  3. En Supabase, Authentication, Users: confirma que existe el usuario con el que vas a entrar a la web.
  4. En Supabase, Database, Publications: la publicación supabase_realtime debe incluir mediciones, nodos, clima_cultivo, alertas, ajustes_simulacion, solicitudes_ia y sugerencias_ia. La migración las agrega sola si la publicación existe.
Las migraciones 0009 a 0012 se probaron en una base local de pruebas (70 pruebas). No se han aplicado todavía a tu proyecto real. Si migrar muestra un error, no sigas: copia el mensaje y lo revisamos.

4. Subir el código

Render despliega lo que esté en GitHub. Hoy el trabajo está sin confirmar en la carpeta de integración. El orden es: revisar, confirmar y subir. La subida la haces tú.

cd ~/Escritorio/AgroVIgia/AgroVigia-integracion
git status
git add -A
git commit -m "Escenario unico, simulacion manual, ingesta HTTP y despliegue en Render"
git push -u origin camilo/integracion-ia-zonas

Antes de confirmar, comprueba que git status no lista .local, .env.local ni node_modules. Están ignorados, pero conviene mirarlo.

5. Crear los servicios en Render

El archivo render.yaml de la raíz describe los dos servicios. Render lo llama Blueprint.

  1. Entra a dashboard.render.com, elige New y después Blueprint.
  2. Conecta tu cuenta de GitHub y elige el repositorio y la rama camilo/integracion-ia-zonas.
  3. Render lee render.yaml y te pide los valores marcados como secretos. Escríbelos así:
ServicioVariableValor
agrovigia-webVITE_SUPABASE_URLLa URL del proyecto, por ejemplo https://xxxx.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEYLa clave publicable
agrovigia-n8nSUPABASE_URLLa misma URL
SUPABASE_SECRET_KEYLa clave secreta
GEMINI_API_KEYLa clave nueva de Gemini

Estas otras las pone el plano y no tienes que escribirlas:

VariablePara qué
AGROVIGIA_INGESTA_CLAVEClave del webhook. Render la genera. La simulación la usa sola porque vive en el mismo contenedor.
N8N_ENCRYPTION_KEYCon ella n8n cifra sus credenciales. Render la genera.
AGROVIGIA_SIMULADOR=siEnciende la simulación dentro del contenedor.
GENERIC_TIMEZONEHora de Colombia para los disparadores.

El puerto y la dirección pública no se configuran: el arranque los toma de las variables que Render inyecta (PORT, RENDER_EXTERNAL_URL).

  1. Pulsa Apply. La web tarda uno o dos minutos. n8n tarda más la primera vez porque descarga la imagen y prepara su base interna.
  2. En el registro de agrovigia-n8n deben aparecer, en este orden: la importación de credenciales, la publicación de los flujos, la frase AgroVigia: credenciales y flujos importados y publicados. Iniciando n8n. y, cuando n8n ya responde, AgroVigia: iniciando el servicio de simulacion contra el webhook local.
n8n no guarda nada entre reinicios, y está pensado así. El plan gratuito no tiene disco. En cada arranque el contenedor vuelve a crear las credenciales desde las variables de entorno e importa los flujos del repositorio. Si entras a la pantalla de n8n te pedirá crear el usuario dueño otra vez: es normal, y los flujos trabajan igual aunque no entres. Para cambiar un flujo se cambia en el repositorio y se vuelve a desplegar.

6. Comprobar que todo responde

n8n está arriba

curl -s https://agrovigia-n8n.onrender.com/healthz

Debe responder {"status":"ok"}. Cambia el nombre por el que Render le haya dado al servicio.

El webhook está protegido

curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  https://agrovigia-n8n.onrender.com/webhook/agrovigia/telemetria \
  -H "Content-Type: application/json" -d '{}'

Sin la clave debe responder 403. Con la clave y un cuerpo vacío responde 400 con el código del problema. Un lote válido responde 200. Si Supabase no confirma, responde 503 y quien envía debe reintentar.

La simulación llega a la web

  1. Abre la web (https://agrovigia-web.onrender.com) e inicia sesión.
  2. En Escenario, los nodos simulados deben pasar a "Recibiendo" con el punto titilando en menos de un minuto.
  3. Activa "Lluvia fuerte". En unos segundos cambian los valores y en unos dos minutos llegan al efecto completo. Deben verse las gotas en el hexágono.
  4. Mueve la regla de humedad del suelo hacia la izquierda y aplica. En Alertas, con "Datos simulados", debe abrirse la alerta cuando el valor baje del mínimo.
  5. En IA pulsa "Analizar ahora". En menos de un minuto debe aparecer la sugerencia con la etiqueta "A petición".
  6. En Historial, al final, el registro de la simulación debe listar el clima y el ajuste con su hora.

7. Mantenerlo despierto

Un servicio web gratuito de Render se duerme a los 15 minutos sin visitas desde fuera y tarda cerca de un minuto en despertar. La simulación no cuenta como visita porque llama desde dentro del contenedor. Mientras n8n duerme no hay simulación, ni alertas, ni sugerencias.

Solución sin costo: un monitor externo que visite /healthz cada 10 minutos. Sirve UptimeRobot o cron-job.org, ambos con plan gratuito. Con un solo servicio despierto todo el mes se usan unas 730 de las 750 horas.

Si creas un segundo servicio web gratuito y lo mantienes despierto, las horas se agotan antes de fin de mes y Render suspende ambos hasta el mes siguiente. Por eso la web va como sitio estático, que no consume horas ni se duerme.

8. El nodo físico

El ESP32 lee tres cosas: temperatura del aire y humedad del aire con el DHT22, y un índice de luz de 0 a 100 con el LDR (no son lux). Envía un lote por minuto.

Hay dos firmware en el repositorio:

FirmwareCómo envíaSirve con RenderEstado
nodo-dht22-mqttMQTT sin cifrar a un computador de la misma red. El Wi-Fi y el servidor van fijos al compilar.No. Render no abre puertos de MQTT.Es el que usa hoy agv-dht22-01.
nodo-agrovigia-httpHTTPS a /webhook/agrovigia/nodo con el código y la clave propia del nodo. El Wi-Fi, el servidor y la clave se configuran por USB desde la web.Sí.Compila y pasa sus pruebas en el computador. No se ha probado en una placa.

Poner en marcha una placa nueva desde la web

  1. Abre la web en Chrome o Edge, en un computador. Otros navegadores y los teléfonos no permiten hablar con la placa por USB.
  2. En Dispositivos pulsa "Registrar nodo físico". Se crea el nodo con su código y una clave propia. La clave no se muestra: pasa directo a la placa en el paso 4.
  3. Conecta la placa por USB y pulsa "Instalar firmware en la placa". El navegador pide elegir el puerto. Instalar borra la configuración que tuviera la placa.
  4. Pulsa "Conectar placa", escribe la red Wi-Fi, su contraseña y la dirección del servidor, y pulsa "Enviar configuración a la placa". La dirección es la de tu n8n seguida de /webhook/agrovigia/nodo.
  5. Con "Leer sensores" compruebas el DHT22 y el LDR. Con "Enviar un lote ahora" compruebas el recorrido completo hasta el servidor.
  6. Cierra el asistente, vincula el nodo a un cultivo y ubícalo en su sector desde Cultivos, Terreno y sectores.
Para no escribir la dirección cada vez, define VITE_AGROVIGIA_NODO_URL en el sitio estático con la dirección completa del webhook. No es un secreto.

Cómo se protege: cada placa envía su código y su clave en dos cabeceras. El servidor guarda solo la huella de la clave y nunca puede volver a mostrarla. Si una placa se pierde, "Generar clave nueva" deja sin efecto la anterior. La contraseña del Wi-Fi y la clave viajan solo por el cable USB: no pasan por Supabase.

Límites conocidos del firmware nuevo. Las claves quedan guardadas en la placa sin cifrar. El firmware verifica el certificado del servidor, pero no rechaza uno vencido por su fecha. Y todo esto está sin probar en una placa real: la primera carga hay que hacerla con el monitor serie a la vista.

El webhook compartido /webhook/agrovigia/telemetria sigue rechazando datos reales: lo usa solo la simulación.

10. Qué mejorar después

  1. Probar el firmware nuevo en una placa y, después, cifrar la configuración guardada en ella.
  2. Guardar n8n en la base de Supabase. Configurando n8n con PostgreSQL conserva usuarios, flujos e historial de ejecuciones entre reinicios.
  3. Plan de pago para n8n. Desde el plan más básico el servicio no se duerme y deja de hacer falta el monitor externo.
  4. Actualización remota del firmware, para no tener que conectar la placa por USB en cada versión.
  5. Dominio propio para la web y para n8n, y restringir en Supabase las direcciones permitidas para iniciar sesión.
  6. Avisos al agricultor fuera de la web (correo o mensajería) cuando se abre una alerta. n8n ya tiene el punto donde engancharlo.
  7. Validar en campo los rangos del catálogo de cultivos y los efectos de cada evento de clima. Hoy son valores de prueba.
